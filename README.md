# QChat Lens

把 QQ 聊天记录变成可检索、可回顾、可洞察的个人知识库。

**核心理念：原始消息一字不改全部保留，AI 在数据之上叠加“理解”——标签、摘要、专题。让你像翻一本带目录的书一样，浏览自己的对话历史。**

## 特性

- **原文永远保留**：每条消息的完整原文与原始数据（JSON）都存在本地 SQLite，AI 分析只是叠加层，随时可重建、可审计。
- **多维标签**：AI 为消息自动打标签（主题/类型/人物…），支持人工修正；标签即检索入口。
- **专题归纳**：AI 把时间线聚类成“专题卡片”（如某门课、某次竞赛、某个项目），点开回到关联原文。
- **四重视图**：概览仪表盘（活动热力图 / 标签云 / 类型计数）、消息时间线（逐条原文 + 详情抽屉）、专题浮窗、图片图库。
- **精准检索**：关键词 / 标签 / 日期 / 消息类型（链接·图片·文件·语音）自由组合过滤，即时跳转。
- **增量分析**：实时新消息自动入库排队，攒够一批才消费 token 做摘要 + 打标，成本可控。
- **任意 OpenAI 兼容 LLM**：DeepSeek / MiniMax / 智谱 / Kimi / Ollama 均可，不锁定厂商。
- **本地优先**：数据、分析、界面全在你自己的电脑上，不上传任何聊天内容。

## 工作原理

```
┌────────────────────────────────────────────────────────────┐
│                        前端 React + Vite                     │
│   概览(热力图/标签云)  消息时间线+详情   专题浮窗   图库       │
└───────────────────────────┬────────────────────────────────┘
                            │ REST /api
┌───────────────────────────▼────────────────────────────────┐
│                     FastAPI (backend/app)                   │
│   sessions · messages · tags · topics · analyze · import    │
│                                                            │
│   Analyzer：分批摘要+打标 → SQLite    专题归纳(时间切片)      │
└───────────────────────────┬────────────────────────────────┘
                            │
              ┌─────────────┼─────────────────┐
              ▼             ▼                 ▼
     聊天记录历史导出    实时增量监听         (可扩展)其它源
     (QQ 云端全量)      (登录中的新消息)
```

## 数据来源

| 来源 | 作用 | 说明 |
|---|---|---|
| QQ 云端历史 | 全量历史 | 通过 QQ Chat Exporter 导出为 JSON 后导入（含经云同步迁移过来的老版本记录） |
| QQ 登录端实时推送 | 实时增量 | NapCat 作为 OneBot11 服务端，通过 WebSocket 把每条新消息推给应用 |

> 两者都可选：只想一次性回顾历史可以只做全量导入；想长期自动收集新消息再挂实时监听。
> 实时监听默认按**允许名单**收录，未加入名单的会话一律不入库（详见「配置」）。

## 快速开始

### 环境要求

- Python 3.10+
- Node.js 18+
- （可选）一条可用的 OpenAI 兼容接口（用于 AI 标签/摘要/专题；不配也能纯浏览）

### 克隆与启动

```bash
git clone <本仓库地址>
cd qchat-lens
```

**后端**

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8770
```

**前端**（任选其一）

开发模式：

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173（已代理 /api 到 8770）
```

或构建后交给后端托管：

```bash
npm run build      # 产物 dist/，FastAPI 自动托管
```

浏览器打开 http://127.0.0.1:8770 即进入应用。

### 首次使用

1. 打开右上角「配置 / 导入」→ **LLM** 页签：填入 `API 地址 / Key / 模型`（任意 OpenAI 兼容接口，地址通常以 `/v1` 结尾），点「保存」→「测试连接」。
2. 在 QQ Chat Exporter（QCE）里登录并保持运行，切到「导入数据」页签选择要导入的好友/会话，点「同步并导入完整历史」。
   > 若不使用 QCE，也可等待实时监听自动收录新消息（需先配置允许名单）。
3. 回到主界面进入该会话，点「分析 / 重建专题」让 AI 开始打标签、归纳专题。
4. 之后随时回来：按标签 / 日期 / 类型筛选，或点开专题浮窗回顾整段脉络。

## 数据库结构

```
sessions      会话（friend:<uin> / group:<gid>）
messages      消息（msg_key 幂等、ts 时间、text 归一文本、raw 原始JSON全文）
tags          标签词典
message_tags  消息 × 标签 关联
topics        专题卡片（title / summary / 覆盖消息 id 区间）
analysis_log  分析执行日志（可审计、可重建）
resources     图片 / 文件资源登记（路径、MIME、尺寸）
```

## LLM 策略与成本

- **消息级 + 摘要混合**：实时消息攒批（默认 80 条）→ 一次 LLM 调用产出该批的多维标签 + 摘要 + 待办 + 关键事实，标签写回每条消息。
- **专题归纳**：对整个会话按约 120 条切片，逐片让 LLM 输出「专题 → 消息区间」映射，存入 topics。
- **成本可控**：只有 `analyzed=0` 的消息才触发分析，重复触发不重复消费 token；`/api/analyze` 幂等。
- **人工优先**：标签可人工增删（`source=manual`），后续分析自动避开已人工修正的消息。

## 配置

后端配置位于 `backend/config.json`（首次运行自动生成），也可在界面「配置 / 导入」中维护：

```json
{
  "llm": { "base_url": "", "api_key": "", "model": "" },
  "database": "<data>/qchat.db",
  "resources_dir": "<data>/resources",
  "qce": { "base_url": "http://127.0.0.1:40653" },
  "napcat": { "ws_url": "ws://127.0.0.1:3001" },
  "whitelist": { "private": [], "groups": [] }
}
```

- **`whitelist`（建议配置，隐私 + 省 token）**：**允许名单**。实时监听只收录 `private` / `groups` 中列出的会话（按 uin / gid），空列表 = 不收录任何实时消息。全量导入不受此限制。
- **LLM**：任意 `chat/completions` 兼容服务均可。

## 隐私与安全

- 聊天原文与元数据只存在于本机 SQLite，界面不依赖任何外部服务；唯一网络请求是发给你自配的 LLM（且只发送消息文本用于分析）。
- 建议开启实时监听允许名单，避免无关会话被自动入库。
- 第三方 QQ 协议端非官方，存在被平台风控/限制的风险，请知悉后自担风险使用。

## 常见问题

**没有配 LLM 能用吗？**
能。可正常导入、浏览、检索；仅标签 / 摘要 / 专题等 AI 功能不可用。

**为什么某些会话没在侧栏显示？**
被隐藏或不在实时允许名单内。所有会话数据不会因隐藏而删除，可在后端 `/api/sessions?include_hidden=true` 或按需恢复。
